영어 발표 초안과 수술주기별 촬영 계획을 함께 보는 웹페이지입니다.

## 현재 발표 구성

[웹 발표 검토](https://notoow.github.io/vietnam-urology-webinar/#design)

발표 슬라이드 상단의 **PNG ▼**는 전체 24장(1920 × 1080 PNG)의 ZIP을, **PPT ▼**는 영상 7편과 GIF를 포함한 완성 PowerPoint 파일을 바로 내려받습니다. 현재 다운로드는 2026-10-16 v4 완성본입니다. 배포 파일은 GitHub Release `webinar-2026-10-17-v4`에 저장하고, 링크·파일명·용량은 `src/downloads.json`에서 관리합니다. 대용량 PPTX와 PNG ZIP은 웹 소스 저장소에 포함하지 않습니다.

앞으로 웹 발표를 수정할 때는 PNG ZIP과 PPTX도 같은 내용으로 갱신하고 다운로드 링크까지 함께 배포합니다. 웹과 다운로드 파일의 버전 일치를 확인해야 수정이 완료됩니다. 세부 작업 규칙은 [AGENTS.md](AGENTS.md)에 있습니다.

공개 화면의 문구는 방문자를 대상으로 작성합니다. 제작자가 사용자에게 하는 작업 보고, 전달받은 자료에 대한 응답, 편집·구현 상태는 사진 설명·발표 해설·일정·입력 안내에 넣지 않습니다. 재료명·규격·발표 내용과 실제로 필요한 사용 안내만 표시합니다. 미확인 임상값은 추정하지 않고 비워두며, 출처 및 제작 기록은 공개 설명과 구분해 관리합니다.

발표는 총 24장입니다. 표지, 원장님 소개, MegaDerm·MegaFill, 수술 전 평가, 공통 드랩, 실제 네 증례(각 3장), 음경 전체 합병증, 진피 관련 형태·길이 변화, 진피 윤곽·위치 변화, 진피 변화 GIF 종합 비교, 포경선·치골절개 후관리(각 1장), Q&A 순서입니다. 드랩은 증례 시작 직전에 한 번만 보여줍니다.

- Case 1: T-ring Removal and Dermal Grafting — Pubic incision (2026-10-12)
- Case 2: Dermal Grafting — Circumcision-line incision (2026-10-12)
- Case 3: Two-sheet Dermal Grafting — Circumcision-line incision (2026-10-14)
- Case 4: Circumcision and Dermal Grafting — Circumcision-line incision (2026-10-14)

증례마다 환자 요약과 사진, 16:9 수술 영상, 전후 비교를 배치했습니다. 요약 페이지는 네 증례 모두 Preoperative photograph와 수술 전 길이·굵기·귀두 둘레를 표시합니다. 수술 전 사진은 전후 비교의 Before 파일을 사용하며, 16:9 영역에 맞춰 비율을 유지한 확대 크롭을 적용합니다. 사이드바에서는 Case 1–4의 세 장씩 묶인 목록 사이에 구분선을 표시합니다. 전후 비교에는 2026-10-16 제공된 네 증례의 사진 8장과 Case 1의 제거된 T-ring 사진을 사용합니다. 사진은 방향을 보존한 JPEG 사본으로 만들고 메타데이터를 제거했습니다.

완성된 드랩·Case 1–4·절개별 후관리 영상 7편은 1080p H.264/AAC, 29.97 fps, fast-start MP4 사본으로 제공합니다. 편집본의 장면·순서·재생 길이는 유지하며 원본은 변경하지 않았습니다. 영상 영역은 896×504입니다. 클릭하기 전에는 영상을 다운로드하지 않으며 슬라이드나 탭을 떠나면 재생을 일시 정지합니다. 공개 파일명은 증례 번호만 사용합니다. Case 3의 완성 편집본은 사용자가 그대로 공개하도록 확인했으며, 두 장의 겹침 방법에 관한 추가 설명은 넣지 않습니다.

증례 프로필 표에는 Age / Incision / Graft size를 표시하며, 아래에 Preoperative measurements 표를 배치합니다. Case 3의 진피는 5 × 6 cm와 6 × 12 cm 두 장입니다. Case 4는 길이 8→8 cm, 굵기 7.5→11 cm, 귀두 둘레 8→9 cm를 반영했습니다. 절개법은 Case 1의 치골절개, Case 2–4의 포경선 절개로 확인되었습니다. 2026-10-16 전달된 실측값을 반영했습니다. Case 1은 길이 5→7 cm, 굵기 8→9 cm, 귀두 둘레 8→9 cm이고 Case 2는 길이 4.5→7 cm, 굵기 8→9 cm, 귀두 둘레 8→9 cm입니다. 각 증례 첫 장에는 수술 전 값을 표시합니다. 측정 상태·수술 후 경과 시점은 비워둡니다. 사진만으로 임상 수치를 추정하지 않습니다. 파일명의 약어를 임상 정보로 해석하지 않았으며 환자 이름과 원본 폴더 경로는 발표 데이터에 넣지 않았습니다. 기존 37세·30세 증례는 구성만 참고하고 사진·정보·수치를 사용하지 않았습니다.

승인된 디자인의 흰 배경, 골드 포인트, Pretendard와 원본 로고를 유지합니다. 본문은 `src/deck.json`, 공통 배치는 `scripts/layout-deck.cjs`에서 관리합니다. 이미지와 문안 출처는 각 증례의 `provenance`와 준비 메모에 기록하며 환자명은 저장하지 않습니다.

수술 전 평가는 승인된 한 장의 구성으로 통합했습니다. IIEF/PEDT 설문, 혈액·감염 선별검사, 신체진찰·음경 길이 측정·진동각 검사를 모두 포함합니다. 길이는 flaccid/stretched 상태로 표기합니다. 검사 목록은 혈액응고검사(PT/PTT), TTT(testosterone), CBC, PSA, Blood glucose (BST/HbA1c), HIV, 매독, 소변검사, Liver enzymes (GOT/GPT/GGT), 염증수치입니다. HbA1c는 별도 행 대신 혈당 항목에 포함합니다. 2장에 원장님 학력·경력, 교육·지정 경력, 수상 및 학회 회원 이력을 영어로 정리했습니다. 22장에는 포경라인 후관리, 23장에는 치골라인·더마본드 후관리 영상을 연결했습니다. 합병증 목록은 발표자 실적이나 발생률이 아닌 문헌 기반 초안입니다. 18장 오른쪽의 피부 부종·봉합·감각신경 그림은 합병증 범주를 설명하는 생성 도해이며 실제 환자 사진이나 임상 결과 자료가 아닙니다. 출처는 `src/deck.json`의 해당 슬라이드 참고 문안과 `sources`에 있습니다.

21장 진피 변화 GIF의 오른쪽 위에 순환 시계를 표시합니다. 정상 모습에서 변화한 모습으로 전환했다가 정상으로 돌아오는 5.3초 동안 바늘이 시계 방향으로 한 바퀴 회전합니다. 시계와 그림은 동일 GIF의 50ms 프레임으로 묶었으며 기존 그림의 픽셀·배치·대기 시간을 유지합니다. 동작 줄이기 설정에서는 시계 없는 정지 비교 그림을 표시합니다.

촬영 기록과 발표 문안을 분리했습니다. 촬영 메모를 발표 화면이나 PPTX 노트에 자동으로 가져오지 않습니다. 발표에는 원내 세부 노하우를 넣지 않습니다.

PPT의 실제 발표자 노트에는 슬라이드마다 영어 핵심어 한 줄만 넣습니다. 웹에서도 슬라이드 아래 **Keywords** 한 줄로 같은 내용을 보여줍니다. `src/deck.json`의 `speakerCueLine`에서 관리하며, 접힌 한국어 요약에는 해당 슬라이드의 발표 내용만 표시합니다. 상세 영어 문안·출처는 원본 데이터에 보존합니다. 슬라이드를 바꾸면 메모도 바뀝니다. 전체 화면 발표 모드에서는 웹 메모가 보이지 않습니다.

발표 문안은 `src/deck.json`, 웹·PPTX 공통 배치는 `scripts/layout-deck.cjs`에서 관리합니다. 표지·평가·증례 영상은 `src/design-study.json`의 승인된 배치를 재사용합니다. 기존 수술팀 촬영 기록은 별도로 유지합니다. 이 기록의 공개 범위는 발표 자료와 다르며, 기존 공개 링크의 기록은 계속 읽을 수 있습니다.

## 영상팀 사용 방법

일반 링크를 열면 회원가입·로그인·전용 키 없이 누구나 같은 촬영 목록을 편집합니다.

1. 카드의 촬영 종류에서 **사진 / 영상 / 사진 + 영상 / 촬영 불필요**를 고릅니다.
2. 카드 아래 **＋ 씬 추가**로 촬영할 장면을 여러 개 적고 저장합니다. 씬의 **×**를 누르면 삭제 여부를 확인합니다. 기존 메모는 첫 번째 씬으로 유지됩니다.
3. 필요한 과정을 추가하거나 이름·순서를 바꾸고, 촬영 후 완료 표시를 누릅니다.
4. 실수로 수정·삭제했으면 **되돌리기**에서 변경 전 내용을 확인해 복원합니다.
5. **링크 복사**로 공유합니다.

촬영원본은 시놀로지 공유 폴더에서 봅니다. 상단에 연결 자리를 마련했으며 URL은 추후 전달받아 src/filming-source.json의 url에 넣고 빌드합니다. 현재는 **공유 링크 준비 중**으로 표시합니다. 영상 파일을 Supabase에 업로드하지 않습니다.

저장한 변경은 다른 화면에 실시간 반영됩니다. 같은 과정을 동시에 수정하면 버전을 비교해 뒤늦은 덮어쓰기를 거절합니다. 문장 단위 동시 타이핑 편집기는 아닙니다.

담당자·소요시간·관리·준비물·대응·기록 입력은 비활성화했습니다. 기존 값은 서버에서 보존하며 공개 편집 요청으로 변경할 수 없습니다.

수술실장에게 전달받은 검사·쉐이빙·혈압·마취·소독·테가덤·수술포·진피 수화·MegaFill·유착방지제·PDRN 내용을 촬영 초안에 반영했습니다. 미확인 약물명·용량·세부 순서·효과 근거는 확정하지 않았습니다. 새 배포용 기본 목록은 29개 과정이며 실제 팀 수정은 Supabase에 저장됩니다.

## 저장과 보호

- GitHub Pages는 화면, Supabase는 공동 데이터와 변경 이력을 저장합니다.
- 공개 publishable key만 브라우저에 포함합니다. 관리자 키·DB 비밀번호는 사용하지 않습니다.
- 방문자는 촬영 계획 전용 RPC만 사용합니다. 내부 테이블은 비공개 스키마에 있고 RLS가 켜져 있으며 방문자에게 테이블 권한이 없습니다.
- 서버에서 허용 필드·자료형·글자 수를 검사합니다. 카드당 씬 20개, 씬 메모 합계 4,000자(구분 줄 포함), 과정명 160자, 구간명 100자, 요청 JSON 40KB 한도입니다. HTML 태그·실행 URL·일부 제어문자를 거절하고 화면은 textContent로 표시합니다.
- 스크립트는 빌드 시 계산한 CSP 해시로 제한하고 외부 연결은 해당 Supabase 프로젝트로 제한합니다.
- 전체 저장은 최근 1분 60회 / 1시간 600회 / 1일 2,000회, 한 과정은 1분 8회, 삭제는 전체 1분 5회로 제한합니다. IP·클라이언트 식별자를 바꿔도 이 공통 한도를 우회할 수 없습니다. 정상 편집도 한도에 도달하면 잠시 대기합니다.
- 삭제한 과정도 보관합니다. 변경 전·후 내용은 방문자가 고치거나 지울 수 없는 이력에 남습니다. 복원도 같은 검사와 제한을 통과합니다.
- 총 과정 200개 / 구간 20개까지입니다. 삭제 항목도 한도에 포함해 무제한 생성·삭제를 막습니다.
- Realtime에는 다시 읽으라는 신호만 보냅니다. 클라이언트의 신호 처리 빈도도 제한합니다.
- 이전 전용 키 API는 실행 권한을 회수했습니다.

공개 편집 문서이므로 현재 내용과 복원용 이전 내용은 누구나 읽을 수 있습니다. 이 공간은 공통 촬영 계획용이며 환자별 정보나 비밀 자료를 넣는 곳이 아닙니다. 익명 편집에서 허용 범위 내의 고의적 내용 훼손을 완전히 판별할 수는 없습니다. 위 제한은 데이터 변경 속도와 규모를 줄이며 대규모 네트워크 공격이나 서비스 중단 방지를 보장하지 않습니다.

문제가 발생하면 프로젝트 소유자가 SQL Editor에서 아래 문장으로 이 촬영 목록의 쓰기만 일시 중지할 수 있습니다. 조회와 이력은 유지됩니다.

~~~sql
update highst_filming_private.settings set public_editing=false where id;
~~~

재개할 때는 false를 true로 바꿉니다. 원본 이력은 별도 보존되며 방문자용 영구 삭제 API는 없습니다.

## 개발과 검증

~~~sh
npm ci --ignore-scripts
npm run build
~~~

src/를 수정한 뒤 빌드한 index.html과 highst-review.html을 함께 커밋합니다. 두 경로 모두 정적 OG 메타태그를 포함해 공유 미리보기가 자바스크립트 없이 읽힙니다. 원본 로고 파비콘과 1200×630 공유 이미지는 assets/에 있습니다. 화면을 새로 배포해도 기존 Supabase 기록은 덮어쓰지 않습니다.

DB 변경은 supabase/migrations/에 있습니다. 새 설치에는 순서대로 마이그레이션을 적용하고 filming-seed.json을 한 번만 초기화합니다. 현재 공개 편집 방식에는 팀 키 설정이 필요 없습니다.

supabase/tests/public_filming.sql은 실제 anon 역할로 입력 제한·비활성 필드 보호·동시 수정 충돌·삭제/복원·이력·이전 API 차단·요청 제한을 검증합니다. 모든 테스트 데이터는 트랜잭션 종료 시 롤백됩니다.

supabase/tests/filming_scenes.sql은 다중 씬·촬영 종류의 저장/복원, 기존 메모 호환, 한글 4,000자, 잘못된 입력 및 오래된 클라이언트의 덮어쓰기 거절을 검증합니다. 이 테스트도 롤백됩니다.

API 권한 분리는 [Supabase 공식 가이드](https://supabase.com/docs/guides/api/securing-your-api)를 참고했습니다. 다른 서비스의 테이블이나 프로젝트 전체 인증 설정은 이 앱의 마이그레이션에서 변경하지 않습니다.

로고와 사진의 권리는 원 권리자에게 있습니다. Pretendard 및 Supabase 클라이언트 라이선스는 assets/에 포함했습니다.
