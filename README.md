# HIGHST · Vietnam Urology Webinar

영어 발표 초안과 수술주기별 촬영 계획을 함께 보는 웹페이지입니다.

[촬영 계획 열기](https://notoow.github.io/vietnam-urology-webinar/#perioperative)

## 현재 발표 구성

[영어 발표 보기](https://notoow.github.io/vietnam-urology-webinar/#design) · [편집 가능한 PPTX](downloads/highst-perioperative-webinar.pptx)

발표는 제공된 베트남.pdf의 9개 구성 항목을 13장으로 배치했습니다. 표지, 원장님 소개, MegaDerm·MegaFill 소개, 수술 전 검사, 수술 준비 영상, 다섯 증례, 기타 합병증, 수술 후 관리·드레싱, Q&A 순서입니다.

증례는 PDF 순서대로 Case 1 치골절개, Case 2 포경선 절개, Case 3 진피 2차 이식, Case 4 재수술, Case 5 턱짐 교정입니다. 사용자 확인에 따라 다섯 증례를 모두 포함하고 새로 촬영할 영상 영역을 비워두었습니다. 수술 준비 영상도 빈 영역으로 남겼습니다.

진동각 검사는 Penile biothesiometry로 반영했습니다. 원장님 학력·경력, 정확한 혈액·소변검사 항목, 실제 영상과 수술 후 관리 세부 설명은 추가 예정입니다. 합병증 목록은 발표자 실적이나 발생률이 아닌 문헌 기반 초안입니다. 출처는 해당 슬라이드 노트에 있습니다.

촬영 기록과 발표 문안을 분리했습니다. 촬영 메모를 발표 화면이나 PPTX 노트에 자동으로 가져오지 않습니다. 발표에는 원내 세부 노하우를 넣지 않습니다.

발표 문안은 `src/deck.json`에서 관리합니다. 기존 수술팀 촬영 기록은 별도로 유지합니다. 이 기록의 공개 범위는 발표 자료와 다르며, 기존 공개 링크의 기록은 계속 읽을 수 있습니다.

## 영상팀 사용 방법

일반 링크를 열면 회원가입·로그인·전용 키 없이 누구나 같은 촬영 목록을 편집합니다.

1. 카드의 촬영 종류에서 **사진 / 영상 / 사진 + 영상 / 촬영 불필요**를 고릅니다.
2. 카드 아래 **＋ 씬 추가**로 촬영할 장면을 여러 개 적고 저장합니다. 씬의 **×**를 누르면 삭제 여부를 확인합니다. 기존 메모는 첫 번째 씬으로 유지됩니다.
3. 필요한 과정을 추가하거나 이름·순서를 바꾸고, 촬영 후 완료 표시를 누릅니다.
4. 실수로 수정·삭제했으면 **되돌리기**에서 변경 전 내용을 확인해 복원합니다.
5. **링크 복사**로 공유합니다.

촬영원본은 시놀로지 공유 폴더에서 봅니다. 상단에 연결 자리를 마련했으며 URL은 추후 전달받아 src/filming-source.json의 url에 넣고 빌드합니다. 현재는 **공유 링크 준비 중**으로 표시합니다. 영상 파일을 Supabase에 업로드하지 않습니다.

저장한 변경은 다른 화면에 실시간 반영됩니다. 같은 과정을 동시에 수정하면 버전을 비교해 뒤늦은 덮어쓰기를 거절합니다. 문장 단위 동시 타이핑 편집기는 아닙니다.

담당자·소요시간·관리·준비물·대응·기록 입력은 비활성화했습니다. 기존 값은 서버에서 보존하며 공개 편집 요청으로 변경할 수 없습니다.

수술실장에게 전달받은 검사·쉐이빙·혈압·마취·소독·테가덤·수술포·진피 수화·MegaFill·유착방지제·PDRN 내용을 촬영 초안에 반영했습니다. 미확인 약물명·용량·세부 순서·효과 근거는 확정하지 않았습니다. 새 배포용 기본 목록은 29개 과정이며 실제 팀 수정은 Supabase에 저장됩니다.

## 저장과 보호

- GitHub Pages는 화면, Supabase는 공동 데이터와 변경 이력을 저장합니다.
- 공개 publishable key만 브라우저에 포함합니다. 관리자 키·DB 비밀번호는 사용하지 않습니다.
- 방문자는 촬영 계획 전용 RPC만 사용합니다. 내부 테이블은 비공개 스키마에 있고 RLS가 켜져 있으며 방문자에게 테이블 권한이 없습니다.
- 서버에서 허용 필드·자료형·글자 수를 검사합니다. 카드당 씬 20개, 씬 메모 합계 4,000자(구분 줄 포함), 과정명 160자, 구간명 100자, 요청 JSON 40KB 한도입니다. HTML 태그·실행 URL·일부 제어문자를 거절하고 화면은 textContent로 표시합니다.
- 스크립트는 빌드 시 계산한 CSP 해시로 제한하고 외부 연결은 해당 Supabase 프로젝트로 제한합니다.
- 전체 저장은 최근 1분 60회 / 1시간 600회 / 1일 2,000회, 한 과정은 1분 8회, 삭제는 전체 1분 5회로 제한합니다. IP·클라이언트 식별자를 바꿔도 이 공통 한도를 우회할 수 없습니다. 정상 편집도 한도에 도달하면 잠시 대기합니다.
- 삭제한 과정도 보관합니다. 변경 전·후 내용은 방문자가 고치거나 지울 수 없는 이력에 남습니다. 복원도 같은 검사와 제한을 통과합니다.
- 총 과정 200개 / 구간 20개까지입니다. 삭제 항목도 한도에 포함해 무제한 생성·삭제를 막습니다.
- Realtime에는 다시 읽으라는 신호만 보냅니다. 클라이언트의 신호 처리 빈도도 제한합니다.
- 이전 전용 키 API는 실행 권한을 회수했습니다.

공개 편집 문서이므로 현재 내용과 복원용 이전 내용은 누구나 읽을 수 있습니다. 이 공간은 공통 촬영 계획용이며 환자별 정보나 비밀 자료를 넣는 곳이 아닙니다. 익명 편집에서 허용 범위 내의 고의적 내용 훼손을 완전히 판별할 수는 없습니다. 위 제한은 데이터 변경 속도와 규모를 줄이며 대규모 네트워크 공격이나 서비스 중단 방지를 보장하지 않습니다.

문제가 발생하면 프로젝트 소유자가 SQL Editor에서 아래 문장으로 이 촬영 목록의 쓰기만 일시 중지할 수 있습니다. 조회와 이력은 유지됩니다.

~~~sql
update highst_filming_private.settings set public_editing=false where id;
~~~

재개할 때는 false를 true로 바꿉니다. 원본 이력은 별도 보존되며 방문자용 영구 삭제 API는 없습니다.

## 개발과 검증

~~~sh
npm ci --ignore-scripts
npm run build
~~~

src/를 수정한 뒤 빌드한 index.html과 highst-review.html을 함께 커밋합니다. 두 경로 모두 정적 OG 메타태그를 포함해 공유 미리보기가 자바스크립트 없이 읽힙니다. 원본 로고 파비콘과 1200×630 공유 이미지는 assets/에 있습니다. 화면을 새로 배포해도 기존 Supabase 기록은 덮어쓰지 않습니다.

DB 변경은 supabase/migrations/에 있습니다. 새 설치에는 순서대로 마이그레이션을 적용하고 filming-seed.json을 한 번만 초기화합니다. 현재 공개 편집 방식에는 팀 키 설정이 필요 없습니다.

supabase/tests/public_filming.sql은 실제 anon 역할로 입력 제한·비활성 필드 보호·동시 수정 충돌·삭제/복원·이력·이전 API 차단·요청 제한을 검증합니다. 모든 테스트 데이터는 트랜잭션 종료 시 롤백됩니다.

supabase/tests/filming_scenes.sql은 다중 씬·촬영 종류의 저장/복원, 기존 메모 호환, 한글 4,000자, 잘못된 입력 및 오래된 클라이언트의 덮어쓰기 거절을 검증합니다. 이 테스트도 롤백됩니다.

API 권한 분리는 [Supabase 공식 가이드](https://supabase.com/docs/guides/api/securing-your-api)를 참고했습니다. 다른 서비스의 테이블이나 프로젝트 전체 인증 설정은 이 앱의 마이그레이션에서 변경하지 않습니다.

로고와 사진의 권리는 원 권리자에게 있습니다. Pretendard 및 Supabase 클라이언트 라이선스는 assets/에 포함했습니다.
